### 1.2 技术债务识别

#### 🔴 P0（高危，影响生产可用性）
1. **知识库全表扫描**：`KnowledgeBaseService.java:297-305` 逐条计算余弦相似度，无向量索引
2. **Agent记忆易失**：`AgentMemoryService.java:18` CopyOnWriteArrayList存储，重启丢失所有会话记忆
3. **工具无权限控制**：所有AgentTool直接执行，无读写分级、无租户隔离、无审计日志

#### 🟡 P1（重要，影响企业级应用）
1. **串行执行浪费**：DAG引擎已做拓扑排序但顺序执行，无依赖节点无法并行
2. **LangGraph条件边缺失**：`GraphBuilder.java:86-91` 仅addEdge，不支持addConditionalEdges
3. **Checkpoint仅DAG可用**：LangGraph引擎无Resume接口，失败无法恢复

#### 🟢 P2（优化，提升工程质量）
1. **Skills无版本管理**：SKILL.md无版本号、签名、来源权限控制
2. **MCP单一工具**：仅支持火山搜索，无通用MCP Server接入能力
3. **失败传播粗暴**：任意节点异常立即throw，无部分成功保存、无补偿重试

### 1.3 性能瓶颈定位（可量化）

| 场景 | 现状指标 | 瓶颈原因 | 目标指标 |
|------|---------|---------|---------|
| **知识库检索** | 1万条：~500ms<br>10万条：>5s | 全表加载 + 逐条余弦计算 | 1万条：<50ms<br>10万条：<200ms |
| **工作流执行** | 10节点串行：~10s | 无依赖节点串行等待 | 10节点并行：~3s（理论） |
| **Agent记忆召回** | 1000条：~100ms | 全表stream过滤 | 1000条：<20ms（索引） |

#### 1.1 知识库向量索引优化

##### 功能方向
**现状**：`KnowledgeBaseService.searchRelevantChunks()` 全表加载 → stream过滤 → 逐条余弦计算  
**目标**：接入pgvector或实现HNSW/IVF近似最近邻算法，检索复杂度从O(n)降至O(log n)

##### 具体实现

**方案A：接入pgvector（推荐，生产级）**
1. 升级数据库：PostgreSQL 15+ 或使用MySQL + TimescaleDB pgvector扩展
2. 表结构调整：
   ```sql
   ALTER TABLE knowledge_chunk 
     ADD COLUMN embedding vector(1536),  -- OpenAI text-embedding-3-small维度
     ADD INDEX idx_embedding USING ivfflat (embedding vector_cosine_ops);
   ```
3. 查询改写：
   ```sql
   SELECT id, content, 1 - (embedding <=> ?::vector) AS score
   FROM knowledge_chunk
   WHERE knowledge_base_id = ?
   ORDER BY embedding <=> ?::vector
   LIMIT ?;
   ```

**方案B：自研ANN算法（无法升级数据库时）**
1. 实现HNSW（Hierarchical Navigable Small World）简化版
2. 启动时加载向量到内存，构建多层邻近图
3. 查询时从顶层导航到底层，贪心搜索最近邻

```java
@Service
public class AgentMemoryService {
    @Autowired private AgentMemoryMapper memoryMapper;
    @Autowired private RedisTemplate<String, String> redis;
    
    public void saveMemory(MemoryRecord record) {
        // 1. 计算TTL
        record.setExpiresAt(calcExpireTime(record.getScope()));
        
        // 2. 持久化到MySQL
        memoryMapper.insert(record);
        
        // 3. 同步到Redis（SESSION/WORKING级别）
        if (record.getScope() == MemoryScope.SESSION) {
            String key = "agent:memory:session:" + record.getSessionId();
            redis.opsForList().leftPush(key, JSON.toJSONString(record));
            redis.expire(key, 30, TimeUnit.MINUTES);
        }
    }
    
    public List<MemoryRecord> searchMemories(String sessionId, String query, int topK) {
        // 1. 先查Redis缓存
        String key = "agent:memory:session:" + sessionId;
        List<String> cached = redis.opsForList().range(key, 0, -1);
        if (CollectionUtils.isNotEmpty(cached)) {
            return filterBySimilarity(cached, query, topK);
        }
        
        // 2. 缓存未命中，查MySQL（向量索引）
        List<MemoryRecord> results = memoryMapper.selectByVectorSimilarity(
            sessionId, queryEmbedding, topK
        );
        
        // 3. 回填Redis
        results.forEach(r -> redis.opsForList().rightPush(key, JSON.toJSONString(r)));
        
        return results;
    }
}
```

### 阶段2：运行时增强（P0-P1，2-3周）

#### 2.1 并行DAG调度器

##### 功能方向
**现状**：`WorkflowEngine.java:151-235` 顺序for循环执行节点，无依赖节点串行浪费  
**目标**：基于拓扑排序结果，将入度为0的节点提交到有界线程池并行执行，保持结果确定性

##### 具体实现

**并行调度核心逻辑**
```java
public class ParallelDAGScheduler {
    private final ExecutorService executor = new ThreadPoolExecutor(
        4,  // corePoolSize：根据CPU核心数调整
        8,  // maximumPoolSize
        60L, TimeUnit.SECONDS,
        new LinkedBlockingQueue<>(100),
        new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略：调用者线程执行
    );
    
    public Map<String, Object> execute(
        List<WorkflowNode> sortedNodes,
        Map<String, List<String>> dependencies
    ) {
        Map<String, Object> outputs = new ConcurrentHashMap<>();
        Map<String, Integer> inDegree = calcInDegree(dependencies);
        Queue<WorkflowNode> readyQueue = new ConcurrentLinkedQueue<>();
        
        // 初始化：入度为0的节点加入就绪队列
        sortedNodes.stream()
            .filter(node -> inDegree.get(node.getId()) == 0)
            .forEach(readyQueue::offer);
        
        while (!readyQueue.isEmpty() || hasRunningTasks()) {
            List<CompletableFuture<NodeResult>> futures = new ArrayList<>();
            
            // 批量提交就绪节点
            WorkflowNode node;
            while ((node = readyQueue.poll()) != null) {
                WorkflowNode finalNode = node;
                CompletableFuture<NodeResult> future = CompletableFuture.supplyAsync(
                    () -> executeNode(finalNode, outputs),
                    executor
                );
                futures.add(future);
            }
            
            // 等待本批次完成
            CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();
            
            // 处理结果，更新入度
            for (CompletableFuture<NodeResult> future : futures) {
                NodeResult result = future.get();
                outputs.put(result.getNodeId(), result.getOutput());
                
                // 减少后继节点入度
                List<String> successors = dependencies.get(result.getNodeId());
                if (successors != null) {
                    for (String successor : successors) {
                        int newInDegree = inDegree.merge(successor, -1, Integer::sum);
                        if (newInDegree == 0) {
                            readyQueue.offer(findNode(sortedNodes, successor));
                        }
                    }
                }
            }
        }
        
        return outputs;
    }
}
```

**失败传播与取消**
```java
public CompletableFuture<NodeResult> executeNode(WorkflowNode node, Map<String, Object> outputs) {
    return CompletableFuture.supplyAsync(() -> {
        try {
            // 检查依赖节点是否有失败
            if (hasDependencyFailed(node, outputs)) {
                return NodeResult.skipped(node.getId(), "依赖节点失败，跳过执行");
            }
            
            // 构造输入（聚合上游输出）
            Map<String, Object> input = buildInput(node, outputs);
            
            // 执行节点
            Map<String, Object> output = nodeExecutor.execute(node, input);
            
            return NodeResult.success(node.getId(), output);
            
        } catch (Exception e) {
            log.error("节点执行失败: {}", node.getId(), e);
            
            // 标记失败，取消无关分支
            markFailed(node.getId());
            cancelUnaffectedBranches(node.getId());
            
            return NodeResult.failed(node.getId(), e);
        }
    }, executor);
}
```

#### 2.2 LangGraph条件边补全

##### 功能方向
**现状**：`GraphBuilder.java:86-91` 仅支持固定边addEdge，条件路由无法实现  
**目标**：实现addConditionalEdges，根据上游输出动态选择分支，支持循环节点maxIterations

**条件边核心接口**
```java
@FunctionalInterface
public interface ConditionalRouter {
    /**
     * 根据当前状态和节点输出，决定下一个要执行的节点ID
     * @param state 当前工作流状态
     * @param nodeOutput 上游节点输出
     * @return 下一个节点ID，返回null则结束
     */
    String route(WorkflowState state, Map<String, Object> nodeOutput);
}

// 示例：根据LLM输出的action字段路由
ConditionalRouter llmRouter = (state, output) -> {
    String action = (String) output.get("action");
    return switch (action) {
        case "search" -> "searchToolNode";
        case "calculate" -> "calculatorNode";
        case "finish" -> "END";
        default -> "fallbackNode";
    };
};
```

**GraphBuilder改造**
```java
public class GraphBuilder {
    private final Map<String, ConditionalRouter> conditionalEdges = new HashMap<>();
    
    public GraphBuilder addConditionalEdges(
        String sourceNodeId,
        ConditionalRouter router,
        Map<String, String> pathMap  // 可选的路径显式映射
    ) {
        this.conditionalEdges.put(sourceNodeId, router);
        return this;
    }
    
    public StateGraph<WorkflowState> build() {
        StateGraph<WorkflowState> graph = new StateGraph<>(WorkflowState.class);
        
        // 注册节点
        nodes.forEach((id, adapter) -> graph.addNode(id, adapter));
        
        // 添加固定边
        edges.forEach(edge -> graph.addEdge(edge.getFrom(), edge.getTo()));
        
        // 添加条件边
        conditionalEdges.forEach((sourceId, router) -> {
            graph.addConditionalEdges(sourceId, state -> {
                Map<String, Object> output = state.getNodeOutputs().get(sourceId);
                return router.route(state, output);
            });
        });
        
        graph.setEntryPoint(entryNodeId);
        graph.setFinishPoint(finishNodeId);
        
        return graph.compile();
    }
}
```

```java
public class LoopNode {
    private int currentIteration = 0;
    private final int maxIterations;
    private final Predicate<Map<String, Object>> stopCondition;
    
    public Map<String, Object> execute(Map<String, Object> input) {
        while (currentIteration < maxIterations) {
            Map<String, Object> output = doWork(input);
            
            if (stopCondition.test(output)) {
                output.put("loopFinished", true);
                return output;
            }
            
            currentIteration++;
            input = output;  // 下一轮输入为本轮输出
        }
        
        throw new MaxIterationsExceededException(
            "循环节点超过最大迭代次数: " + maxIterations
        );
    }
}
```

```java
@Component
@Aspect
public class ToolGateway {
    @Autowired private ActionLedgerService ledgerService;
    @Autowired private ApprovalService approvalService;
    @Autowired private TenantContext tenantContext;
    
    @Around("@annotation(toolPolicy)")
    public Object intercept(ProceedingJoinPoint pjp, ToolPolicy toolPolicy) throws Throwable {
        String toolName = pjp.getSignature().getName();
        Object[] args = pjp.getArgs();
        Long tenantId = tenantContext.getCurrentTenantId();
        
        // 1. 租户隔离校验
        if (toolPolicy.requiresTenantIsolation() && tenantId == null) {
            throw new SecurityException("工具需要租户上下文: " + toolName);
        }
        
        // 2. 权限校验
        for (String permission : toolPolicy.requiredPermissions()) {
            if (!hasPermission(tenantId, permission)) {
                throw new PermissionDeniedException("缺少权限: " + permission);
            }
        }
        
        // 3. 根据AutonomyLevel决策
        switch (toolPolicy.level()) {
            case OBSERVE, SUGGEST -> {
                // 直接执行
                return pjp.proceed();
            }
            
            case DRAFT -> {
                // 生成草稿，进入审批队列
                Map<String, Object> draft = (Map) pjp.proceed();
                String approvalId = approvalService.submitForApproval(
                    toolName, args, draft, tenantId
                );
                return Map.of("status", "pending", "approvalId", approvalId);
            }
            
            case EXECUTE -> {
                // 自动执行，但记录审计
                Object result = pjp.proceed();
                ledgerService.recordAction(toolName, args, result, tenantId);
                return result;
            }
            
            case ESCALATE -> {
                // 强制人工确认
                if (!approvalService.isApproved(toolName, args)) {
                    throw new ApprovalRequiredException(
                        "工具需要人工确认: " + toolName
                    );
                }
                Object result = pjp.proceed();
                ledgerService.recordAction(toolName, args, result, tenantId);
                return result;
            }
        }
        
        return null;
    }
}
```

### 4.3 面试追问点准备

#### Q1：并行DAG如何保证结果确定性？
**A**：基于拓扑排序的偏序关系，仅并行无依赖节点。通过ConcurrentHashMap存储输出、CompletableFuture.allOf()等待批次完成，确保后继节点读取的输入顺序与串行一致。失败传播时仅取消受影响分支，保留独立分支的结果。

#### Q2：为什么知识库不用Milvus/Qdrant，而选pgvector？
**A**：考虑部署复杂度和团队技术栈。pgvector作为PostgreSQL扩展，DBA熟悉、运维成本低，IVFFLAT索引在10万级别数据下性能已满足需求（<200ms）。若未来数据量达到千万级，再迁移到专业向量数据库。

#### Q3：AutonomyLevel分级的边界如何划定？
**A**：遵循最小权限原则。OBSERVE：纯查询，无状态改变；SUGGEST：分析类，不写数据库；DRAFT：生成待提交内容，需人工审核；EXECUTE：低风险写操作（如更新备注），自动执行但记录审计；ESCALATE：高风险操作（取消订单、退款），强制人工确认。

#### Q4：如何防止Prompt注入诱导Agent执行越权操作？
**A**：工具层拦截而非LLM层防御。ToolGateway在Spring AOP层拦截所有@ToolPolicy注解的方法，校验租户上下文、权限、AutonomyLevel，LLM无法通过Prompt绕过拦截器直接调用Service层。高风险工具进入ApprovalQueue，人工确认后才执行。

#### Q5：记忆持久化如何处理隐私数据？
**A**：记忆写入前敏感字段脱敏（手机号/身份证号用正则替换为***），USER/TEAM级别记忆强制标注scope，跨用户查询时WHERE条件强制过滤user_id。Redis缓存设置TTL（SESSION级30分钟），过期自动淘汰，MySQL记忆表支持物理删除（GDPR合规）。

## 五、风险与缓解措施

### 5.1 技术风险

| 风险项 | 影响 | 概率 | 缓解措施 |
|--------|------|------|---------|
| **pgvector生产环境不可用** | 无法升级到PostgreSQL | 中 | 提供方案B：自研HNSW算法作为fallback |
| **并行调度引入不确定性** | 测试结果不可复现 | 低 | 保留串行模式开关，回归测试对比串并行输出 |
| **ToolGateway性能开销** | AOP拦截增加延迟 | 低 | 缓存权限校验结果，审计日志异步写入 |
| **LangGraph条件边API变更** | LangGraph4j版本升级破坏性变更 | 中 | 封装适配层，避免业务代码直接依赖三方API |

### 5.2 工期风险

| 阶段 | 预估工期 | 依赖前置 | 延期风险 | 应对措施 |
|------|---------|---------|---------|---------|
| 阶段1 | 2-3周 | 无 | 低 | 优先P0模块，其他顺延 |
| 阶段2 | 2-3周 | 阶段1完成 | 中 | 并行DAG与LangGraph可并行开发 |
| 阶段3 | 2-3周 | 启航ERP AI Tool完成 | 高 | ToolGateway可先接入Mock工具，ERP对接后置 |
| 阶段4 | 按需 | 阶段1-3完成 | - | 可选模块，时间不足可砍掉 |

### 5.3 人力风险

**假设**：1人实习生，每周投入30-40小时  
**总工期**：6-9周（阶段1-3），10-12周（含阶段4）

**关键路径**：
1. 阶段1.1（向量索引）阻塞阶段4.1（混合检索）
2. 阶段3.1（工具权限）阻塞启航ERP对接
3. 阶段2.1（并行DAG）与阶段2.2（LangGraph）可并行

**建议优先级调整**（时间紧张时）：
- **必做**：阶段1（向量索引+记忆持久化）+ 阶段2.1（并行DAG）+ 阶段3.1（工具权限）
- **次要**：阶段2.2（LangGraph条件边）
- **可砍**：阶段4全部
